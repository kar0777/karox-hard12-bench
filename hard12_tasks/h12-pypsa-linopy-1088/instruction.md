Issue:

Dense LinearExpression.to_constraint('==') keeps sign '==': repr raises KeyError, differs from sparse '='

> [!NOTE]
> The following content was generated by AI.

### Version Checks

- [x] I have confirmed this bug exists on the current `master` branch of Linopy (95f6bfa4).

### Issue Description

`LinearExpression.to_constraint("==", rhs)` stores the sign verbatim as `"=="` on the dense backend, while the sparse (CSR) backend normalizes it to `"="`. linopy's canonical equality sign is `EQUAL = "="` (`linopy/constants.py`; `"=="` is only in `SIGNS_alternative`), so the dense backend is the wrong one. Consequences on dense:

- `repr()` of the constraint raises `KeyError: '=='` (`SIGNS_pretty` only knows `"="`).
- The un-normalized `"=="` is carried into the model by `m.add_constraints(con)`.

`x == 1`, `(1*x) == 1` and `m.add_constraints(1*x, "==", 1)` are fine on both backends; only the `to_constraint` path skips sign normalization.

Found while building the dense/sparse conformance suite for #1019 (`test/test_store_conformance.py`, the case marked `SIGN_EQ`, currently a strict xfail on sparse).

### Reproducible Example

```python
from linopy import Model

for sparse in (False, True):
    m = Model(sparse=sparse)
    x = m.add_variables(name="x")
    con = (1 * x).to_constraint("==", 1)
    m.add_constraints(con, name="c")
    print(f"sparse={sparse}: sign={con.sign.item()!r}, stored={m.constraints['c'].sign.item()!r}")
    try:
        print(repr(con))
    except KeyError as e:
        print(f"repr -> KeyError: {e}")
```

Output:

```

repr -> KeyError: '=='
sparse=True: sign='=', stored='='
Constraint (unassigned)
-----------------------
+1 x = 1.0
```

### Expected Behavior

Dense `to_constraint("==", ...)` normalizes the sign to `"="`, as sparse already does and as `x == 1` / `add_constraints(lhs, "==", rhs)` do, so `repr` works and both backends agree. The xfail in the conformance suite can then be dropped.
