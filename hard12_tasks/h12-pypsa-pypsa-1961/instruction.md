Issue:

`primary_energy` GlobalConstraint with `investment_period` set raises `UnboundLocalError` without multi-investment periods

> [!NOTE]
> The following content was generated by AI.

## Version Checks

- [x] I have confirmed this bug exists on the current [`master`](https://github.com/pypsa/pypsa/tree/master) branch of PyPSA.
- [x] Also checked on the `fix/stochastic-scenario-index` branch (PR #1951), which the bug still reproduces on. This bug is independent of scenarios.

## Issue Description

In `define_primary_energy_limit` (`pypsa/optimization/global_constraints.py`),
the local variable `periods` is only assigned inside `if n._multi_invest:`
(around line 321: `periods = window.periods`). Further down, per
`GlobalConstraint`, the code does:

```python
if np.isnan(glc.investment_period):
    period_sns = sns
elif glc.investment_period in periods:
    ...
```

(`pypsa/optimization/global_constraints.py:375`, `:602` for the per-scenario
variant on the branch checked; line 375 also on `master`.)

If a `GlobalConstraint` of type `primary_energy` has `investment_period` set
(not NaN) but the network is *not* using multi-investment periods
(`n._multi_invest` is `False`, i.e. `n.snapshots` is not
`MultiIndex`-by-period), `periods` was never assigned, and the `elif` branch
raises `UnboundLocalError: cannot access local variable 'periods'`.

A related consistency-check warning is already emitted before this
(`"The global constraints contain investment periods but snapshots are not
multi-indexed."`), but the optimization proceeds anyway and crashes with an
unrelated, confusing exception.

## Reproducible Example

```python
import pypsa

n = pypsa.Network()
n.set_snapshots(range(3))
n.add("Carrier", "gas", co2_emissions=1)
n.add("Bus", "b")
n.add("Generator", "g", bus="b", p_nom=100, marginal_cost=1, carrier="gas")
n.add("Load", "l", bus="b", p_set=50)
n.add(
    "GlobalConstraint",
    "co2_limit",
    type="primary_energy",
    carrier_attribute="co2_emissions",
    sense="<=",
    constant=100,
    investment_period=0,
)

n.optimize()
```

## Expected Behavior

Either:
- Raise a clear `ValueError` during consistency checking (upgrading the
  existing warning to an error) when a `GlobalConstraint` has
  `investment_period` set but the network has no multi-investment-period
  snapshots, or
- Treat the network as having a single implicit period and apply the
  constraint to all snapshots, ignoring the (irrelevant) `investment_period`
  value.

Either way, `n.optimize()` should not crash with an `UnboundLocalError` that
gives the user no indication of what is actually wrong.
