Issue:

LP solve fails with `invalid literal for int()` when the objective has no live variable term

> [!NOTE]
> The following content was generated by AI.

### Issue Description

If the objective holds no live variable term (e.g. all its variables are masked), a solve through an LP file (`io_api="lp"` or `"lp-polars"`) fails while reading the solution:

```
ValueError: invalid literal for int() with base 10: 'x'
```

`mps` and `direct` work. Same result with HiGHS and Gurobi.

**Root cause.** Since #1152, such an objective is `is_constant`, so `to_polars()` returns one row with `vars=null, coeffs=null`. `objective_to_file` formats that row with `concat_str(..., ignore_nulls=True)`; only the literal `" x"` survives, and the LP file gets a bare `x` in its objective. The solver reads it as a new column named `x`, and the solution parser cannot turn `x` into a label.

This is the writer bug from #668. That issue was closed by raising an error when no objective is set (#671), so the writer still emits the phantom `x` for an objective that is set but has no live term.

### Reproducible Example

```python
import pandas as pd
import xarray as xr
import linopy

m = linopy.Model()
i = [pd.RangeIndex(2, name="i")]
x = m.add_variables(lower=0, name="x")
z = m.add_variables(lower=0, coords=i, mask=xr.DataArray([False, False], coords=i), name="z")
m.add_constraints(x >= 1)
m.add_objective(z.sum())

m.solve("highs", io_api="lp")  # ValueError: invalid literal for int() with base 10: 'x'
```

LP file objective section:

```
min

obj:

 x
```

### Expected Behavior

The solve succeeds with objective value 0, like `io_api="mps"` and `io_api="direct"`.
