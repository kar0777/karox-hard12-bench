Issue:

add_piecewise_formulation(mask=...) pins fully masked entities to zero instead of skipping them

> [!NOTE]
> The following content was generated by AI.

### Version Checks

- [x] I have confirmed this bug exists on the latest version of linopy (`master`, d78b721e).

### Issue Description

`add_piecewise_formulation(mask=...)` is meant to build **no** formulation where `mask=False` (#799, matching `add_variables`/`add_constraints`). For a fully masked entity it instead keeps the rows with all terms dropped:

- `pwl_convex` gets a `0 = 1` row (dropped at export, so it doesn't make the model infeasible),
- `pwl_link` gets `x[b] = 0` and `y[b] = 0`, which **pins the masked entity's variables to zero**.

### Reproducible Example

```python
import pandas as pd
import xarray as xr

import linopy

m = linopy.Model()
g = pd.Index(["a", "b"], name="g")
x = m.add_variables(lower=0, upper=10, coords=[g], name="x")
y = m.add_variables(lower=0, upper=10, coords=[g], name="y")
mask = xr.DataArray([True, False], coords=[g])
m.add_piecewise_formulation((x, [0, 5, 10]), (y, [0, 4, 10]), name="pwl", mask=mask)
print(m.constraints["pwl_convex"])
print(m.constraints["pwl_link"])
m.add_objective(-x.sum())
m.solve("highs", reformulate_sos=True)
print(m.solution["x"].values)
```

```

[b]: +0                                                            = 1.0
...
[x, b]: +1 x[b] = -0.0
[y, b]: +1 y[b] = -0.0
[10.  0.]
```

### Expected Behavior

No `pwl_convex` / `pwl_link` rows for `b` (labels `-1`), so `x[b]` and `y[b]` stay free within their bounds and the solution is `[10. 10.]`.
