Issue:

9.19.0 needs Git >= 2.43.1

### Describe the problem

### Problem

Since 9.19.0, copying from or updating a git template at a ref fails on git versions older than 2.43.1, with an error from git rather than from Copier. The last lines of the traceback, from the reproduction below:

```
Command line: | /var/folders/.../T/copier-git-repro/git-2.43.0/bin/git -c core.fsmonitor=false checkout -f --end-of-options v1
Stderr:       | error: pathspec '--end-of-options' did not match any file(s) known to git
              | error: pathspec 'v1' did not match any file(s) known to git
```

It's fine if a newer git version is required (I'm simply upgrading to circumvent this issue), but it would be great if the git requirement were documented and a more descriptive error were thrown by Copier. In particular, the README still says "Install Git 2.27 or newer".

Analysis below was generated by AI, as was the reproduction code.

### Analysis

The call was introduced by 6ca1e9d ("fix(vcs): prevent argument injection via `git` subprocess calls") in [`copier/_vcs.py`](https://github.com/copier-org/copier/blob/v9.19.0/copier/_vcs.py#L424):

```python
git("-c", "core.fsmonitor=false", "checkout", "-f", "--end-of-options", ref)
```

`git checkout` (and `git reset`) only accept `--end-of-options` since Git 2.43.1. Older versions keep it in the argument list and treat it as a pathspec. From the [2.43.1 release notes](https://github.com/git/git/blob/master/Documentation/RelNotes/2.43.1.adoc):

> "git $cmd --end-of-options --rev -- --path" for some $cmd failed to interpret "--rev" as a rev, and "--path" as a path. This was fixed for many programs like "reset" and "checkout".

The fix is git/git@9385174 ("parse-options: decouple "--end-of-options" and "--""), which names `git checkout` explicitly.

### To Reproduce

Paste the following into a terminal. It builds Git 2.43.0 and 2.43.1 from the kernel.org tarballs into `$TMPDIR/copier-git-repro` (about a minute each, cached for later runs). Then, for each Git version, it runs a plain `git checkout --end-of-options` and `copier copy --vcs-ref` with Copier 9.18.2 and 9.19.0 from PyPI. It needs a C compiler, `make`, `curl`, `tar` with xz support, zlib headers and [uv](https://docs.astral.sh/uv/). Your own Git configuration is ignored.

```bash
cat > "${TMPDIR:-/tmp}/copier-git-repro.sh" <<'EOF'
#!/usr/bin/env bash
# Reproduces copier 9.19.0 failing on git < 2.43.1.
# Needs: a C compiler, make, curl, tar (with xz), zlib headers, and uv.
set -euo pipefail

GIT_VERSIONS="2.43.0 2.43.1"
COPIER_VERSIONS="9.18.2 9.19.0"
CACHE="${TMPDIR:-/tmp}/copier-git-repro"
mkdir -p "$CACHE"

# Ignore the user's git configuration.
export GIT_CONFIG_NOSYSTEM=1 GIT_CONFIG_GLOBAL=/dev/null

# Build git $1 from the kernel.org tarball into the cache (once) and print its bin dir.
build_git() {
  local version=$1 prefix="$CACHE/git-$1"
  if [ ! -x "$prefix/bin/git" ]; then
    echo "Building git $version (about a minute)..." >&2
    local src
    src=$(mktemp -d)
    curl -sSfL "https://mirrors.edge.kernel.org/pub/software/scm/git/git-$version.tar.xz" | tar xJ -C "$src"
    # Without curl and OpenSSL, imap-send.c in 2.43.1 misses this include and fails to compile.
    sed -i.orig 's/^#include "git-compat-util.h"$/#include "git-compat-util.h"\n#include "strbuf.h"/' \
      "$src/git-$version/imap-send.c"
    make -C "$src/git-$version" -s -j4 prefix="$prefix" \
      NO_GETTEXT=1 NO_TCLTK=1 NO_PERL=1 NO_PYTHON=1 NO_OPENSSL=1 NO_CURL=1 NO_EXPAT=1 \
      install >"$src/build.log" 2>&1 || { tail -20 "$src/build.log" >&2; exit 1; }
  fi
  echo "$prefix/bin"
}

# Report OK, or FAIL with the last lines of the output.
check() {
  local label=$1 log
  shift
  log=$(mktemp)
  if "$@" >"$log" 2>&1; then
    printf '  %-40s OK\n' "$label"
  else
    printf '  %-40s FAIL\n' "$label"
    tail -3 "$log" | sed 's/^/      /'
  fi
}

for git_version in $GIT_VERSIONS; do
  bin=$(build_git "$git_version")
  export PATH="$bin:$PATH"
  echo "$(git --version):"

  # A Git-tracked template tagged v1.
  work=$(mktemp -d)
  git init -q "$work/template"
  echo hello >"$work/template/README.md"
  echo '_min_copier_version: "9"' >"$work/template/copier.yml"
  git -C "$work/template" add .
  git -C "$work/template" -c user.name=x -c user.email=x@x commit -q -m init
  git -C "$work/template" tag v1

  check "git checkout -f --end-of-options v1" git -C "$work/template" checkout -q -f --end-of-options v1
  for copier_version in $COPIER_VERSIONS; do
    check "copier $copier_version copy --vcs-ref v1" \
      uvx --no-config --default-index https://pypi.org/simple -q --from "copier==$copier_version" \
      copier copy --defaults --vcs-ref v1 "$work/template" "$work/project-$copier_version"
  done
  PATH=${PATH#"$bin:"}
done
EOF
bash "${TMPDIR:-/tmp}/copier-git-repro.sh"
```

Output on macOS, starting from an empty cache (the temporary directory path is shortened):

```

git version 2.43.0:
  git checkout -f --end-of-options v1      FAIL

      error: pathspec 'v1' did not match any file(s) known to git
  copier 9.18.2 copy --vcs-ref v1          OK
  copier 9.19.0 copy --vcs-ref v1          FAIL
      Command line: | /var/folders/.../T/copier-git-repro/git-2.43.0/bin/git -c core.fsmonitor=false checkout -f --end-of-options v1
      Stderr:       | error: pathspec '--end-of-options' did not match any file(s) known to git
                    | error: pathspec 'v1' did not match any file(s) known to git
Building git 2.43.1 (about a minute)...
git version 2.43.1:
  git checkout -f --end-of-options v1      OK

  copier 9.19.0 copy --vcs-ref v1          OK
```

So `git checkout --end-of-options` itself fails on 2.43.0 and works on 2.43.1, and Copier 9.19.0 follows the same boundary, while 9.18.2 works on both.
