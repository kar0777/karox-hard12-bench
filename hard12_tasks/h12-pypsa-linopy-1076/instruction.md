Issue:

Constant LinearExpression * multi-term LinearExpression raises TypeError (mirrored product works)

> [!NOTE]
> The following content was generated by AI.

### Version Checks

- [x] I have confirmed this bug exists on the current `master` branch of Linopy (95f6bfa4).

### Issue Description

Multiplying a constant `LinearExpression` (no terms) by a multi-term `LinearExpression` raises `TypeError` on both the dense and sparse backends. The mirrored product (multi-term × constant) and constant × one-term expression both work and return the scaled linear expression.

Cause: `LinearExpression._multiply_by_linear_expression` checks `other.nterm > 1` and raises *before* checking `self.is_constant`. `__mul__` then turns that `TypeError` into `NotImplemented`, so the user only sees the generic `unsupported operand type(s)` message.

Found while building the dense/sparse conformance suite for #1019.

### Reproducible Example

```python
import warnings
from linopy import LinearExpression, Model

warnings.simplefilter("ignore")  # PerformanceWarning on sparse
for sparse in (False, True):
    m = Model(sparse=sparse)
    x = m.add_variables(name="x")
    y = m.add_variables(name="y")
    c = LinearExpression(3, m)
    print(f"sparse={sparse}")
    for lab, f in {
        "c * (2*x + 3*y)": lambda: c * (2 * x + 3 * y),
        "(2*x + 3*y) * c": lambda: (2 * x + 3 * y) * c,
        "c * (2*x)": lambda: c * (2 * x),
        "3 * (2*x + 3*y)": lambda: 3 * (2 * x + 3 * y),
    }.items():
        try:
            r = repr(f()).splitlines()[-1]
        except Exception as e:
            r = f"{type(e).__name__}: {e}"
        print(f"  {lab:18} -> {r}")
```

The same asymmetry applies to non-constant one-term factors, e.g. `(x*0 + 3) * (2*x + 3*y)` raises while `(2*x + 3*y) * (x*0 + 3)` returns a `QuadraticExpression`.

### Expected Behavior

A constant expression acts like a scalar factor: `c * (2*x + 3*y)` returns the `LinearExpression` `+6 x + 9 y`, the same as `(2*x + 3*y) * c` and `3 * (2*x + 3*y)`.
